# Translating a description

A description in the Workspace is not written in one language. Each value, whether a title, a scope and content note or a history, is kept with the language it is in, so the same field can hold an English value, an Afrikaans one and a French one side by side. The public sees the one in its own language where there is one, and the description's own language otherwise.

## Adding a translation

On a description's page, give the language under **Add a translation in**, as a BCP 47 code such as `af` or `fr`, and choose **Translate**. The edit form opens in that language. Fill in the fields you translate and save; a field you leave empty keeps its value in the language it was written in.

Once a description is written in more than one language, **Described in** lists them, each opening the form in that language.

## Names in other languages

Names are translated by adding a name of their own: a parallel form of a title, or an authority record's name in another language, each with its language. Any published name finds the entity in a search.

## Publishing a translation

A translation is a set of new values, and new values start as drafts. Publish them in that language alone from **Publication**, by giving its language, without touching what is already published in the others.

## Translators

The translator role writes values in other languages and nothing else: it can read drafts and add translations, but it cannot change a reference code or a level, publish, or delete. Give it to someone who translates descriptions without cataloguing them.
